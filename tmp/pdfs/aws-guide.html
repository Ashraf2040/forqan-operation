وربط شواهد البرامج

خطوات إعداد PostgreSQL على Amazon RDS وتخزين الملفات في S3 وربطها بالبرنامج ومستوى المتابعة.

الصورة ببساطة

RDS / PostgreSQL يحفظ بيانات الشاهد وعلاقته بالمرحلة والبرنامج والمستوى. S3 يحفظ الملف نفسه. التطبيق يتصل بالخدمتين من الخادم.

مهم

التطبيق الحالي يحفظ الملف محليًا في public/uploads. إنشاء RDS وحده ينقل بيانات السجل فقط. يلزم تعديل مسار الرفع ليستخدم S3 كما في الخطوة الرابعة.

المشروع لديه جدول Evidence في Prisma يحفظ المرحلة ورقم البرنامج واسمه ومستوى المتابعة والحالة والملاحظات وبيانات الملف.

المطلوب

١) إنشاء RDS خاصة. ٢) إنشاء S3 خاص. ٣) ضبط اتصال Prisma. ٤) تعديل الرفع والتنزيل لاستخدام S3.

دليل ربط الشواهد بـ AWS | ١

١. إنشاء قاعدة بيانات RDS

١. افتح AWS Console ثم Amazon RDS → Databases → Create database → Standard create، واختر PostgreSQL.

٢. اختر حجمًا مناسبًا، ومعرّفًا مثل alfurqan-evidence، واسم مستخدم وكلمة مرور قوية.

٣. اختر VPC وشبكات خاصة واجعل Public access = No عند استضافة التطبيق داخل AWS.

٤. في Security Group اسمح بمنفذ 5432 من مجموعة أمان خادم التطبيق فقط. لا تفتحه للعالم (0.0.0.0/0).

٥. فعّل التشفير والنسخ الاحتياطي، راجع التكلفة، وأنشئ القاعدة وانتظر Available.

٦. انسخ Endpoint وPort من Connectivity & security.

إذا كان التطبيق خارج AWS، لا تجعل RDS عامة. الأفضل استضافة التطبيق في AWS أو إنشاء اتصال خاص. لا تستخدم IP مفتوحًا للجميع.

مرجع AWS: إنشاء قاعدة RDS · دليل PostgreSQL

دليل ربط الشواهد بـ AWS | ٢

٢. إنشاء S3 خاص

١. افتح Amazon S3 واختر Create bucket، واكتب اسمًا فريدًا واختر منطقة RDS نفسها.

٢. أبقِ Block all public access مفعّلًا واترك ACLs معطلة؛ ملفات الشواهد خاصة.

٣. فعّل التشفير الافتراضي وVersioning عند الحاجة.

٤. أنشئ IAM Role بصلاحيات محدودة على هذا الـbucket واربطه بخادم التطبيق. لا تضع مفاتيح AWS في المتصفح.

٥. استخدم AWS SDK من الخادم أو روابط موقعة قصيرة العمر للرفع والتنزيل.

مراجع: إنشاء bucket خاص · روابط الرفع الموقعة

٣. ربط Prisma بـ RDS

ضع DATABASE_URL في أسرار الخادم أو .env محليًا، ولا ترفعها للمستودع ولا تستخدم NEXT_PUBLIC_:

DATABASE_URL="postgresql://APP_USER:APP_PASSWORD@RDS_ENDPOINT:5432/DB_NAME?sslmode=require"

استبدل القيم، ورمّز رموز كلمة المرور الخاصة بصيغة URL، وأبقِ sslmode=require.

دليل ربط الشواهد بـ AWS | ٣

٤. إنشاء الجدول وربط الرفع

١. أضف DATABASE_URL إلى بيئة التطبيق أو أسرار الاستضافة.

٢. من مجلد المشروع نفّذ:

npx prisma db push; npx prisma generate

٣. عدّل app/api/evidence/route.ts ليرفع الملف إلى S3 بمفتاح فريد يتضمن المرحلة والبرنامج والمستوى، ثم يحفظ المفتاح والبيانات الوصفية في سجل Evidence بواسطة Prisma.

٤. اجعل API يصدر رابط تنزيل موقّعًا قصير العمر. احفظ مفتاح S3 فقط في قاعدة البيانات، لا الرابط المؤقت.

٥. اختبر بملف غير حساس: تحقق من سجل Evidence الصحيح ومن وجود الملف في S3 ومن عمل التنزيل.

الأمان والتكلفة

لا تفتح RDS أو S3 للعامة. استخدم IAM بصلاحيات محدودة، واحتفظ بنسخ احتياطية، وراقب رسوم RDS وS3. انقل الملفات القديمة من public/uploads إذا أردت الاحتفاظ بها.

حالة المشروع: PostgreSQL وPrisma جاهزان للسجلات. رفع الملفات إلى AWS يحتاج تعديل API. راجع سياسة المدرسة قبل رفع ملفات حساسة.
